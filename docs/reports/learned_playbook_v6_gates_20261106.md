# 可学习 playbook v6 的三道验证门：预注册标准（2026-11-06）

日期：2026-11-06
这份文档是什么：v6（事实维度 A + 写作提示词 B + 实例级目的地事实 C）在正式 V6 之前的
验证门槛与判定标准，写在跑测试**之前**。对应 log.md 的同日条目。

## 为什么要先做这三道门

v1–v4 每一轮都是直接跑完整 K=3（数小时），然后用终测结果反推哪条规则错。
v4 的退步（cool −20.6pp）是写作提示词里一条证据不支持的目的地规则造成的，
这条规则本该在十分钟的离线检查里被看出来。三道门把"文本是否正确"与
"执行是否变好"分开测，每道门都便宜、可重复。

## 门一：离线真实模型试写（不进任何 run）

输入：参考 run `runs/exp3_p0_k3_20261104_2042` 的 P01 答卷；
做法：`tmp/pb_offline.py` 用 config 的 author 模型真实调用一次 `ALFWORLD_PLAYBOOK_WRITE`，
产物落 `tmp/pb_offline_v6*/`。

判定清单（全部满足才算过）：

1. 对称的整词名词规则出现，并含**一个事实里没有的名字对**作为例子；
2. "交付后是否取回"按名词是否一致给出**一句话**优先级，读者不需要权衡；
3. 明确禁止"serves as / counts as"式的合理化；
4. 目的地规则只作用于**确切的编号地点**，且当事实的判定不是 "clearly higher"
   时**完全不出现**禁止访问目的地的句子；
5. 类别交替规则与搜索顺序、目的地规则有衔接说明。

## 门二：受控回放（同库、同任务、只换 playbook 文本）

两条臂，都从 `runs/exp3_lpbz_k3_20261106_1330`（v4，审计通过）`fork-run --through p06`
拷 P01–P06 与 27 个技能，只替换 `phases/p02_learn_add/playbook.md`，然后跑 P07：

| 臂 | run 目录 | playbook 文本 | 用途 |
|---|---|---|---|
| 2a 校准 | `runs/exp3_v6cal_v5text_20261106_1805` | v5（与 0.8134 那次完全相同） | 隔离**推理端点切换**（llmcenter → 自建 vLLM）的影响 |
| 2b 候选 | `runs/exp3_v6text_20261106_1808` | v6 新文本 | 测新事实与新提示词 |

**2a 的判定（端点是否可比）**：avg@3 ≥ **0.760**。v5 文本在同一库上的历史值是
0.8134（llmcenter），因此 0.760 相当于容忍 −5.3pp 的端点差异；低于它说明
自建服务上的行为与参考服务差得太多，2b 的结果不能与历史 run 比较。

**2b 的判定（新文本是否修好 heat 且不伤其他任务）**，与 2a 配对比较：

1. **名词易混题**：avg@3 相对 2a **提升 ≥ +5pp**，且绝对值 ≥ **0.667**；
2. **其余题目**：相对 2a **不低于 −2pp**；
3. **cool 的"从未取到物体"失败数**：≤ **5**（v4 为 19，v3/受控回放为 3–5）。

"名词易混题"的定义（写在看结果之前，只看环境、不看结果）：任务的初始观测或任一
后续观测里，出现一个与任务名词**同族**的其他物体名。"同族" = 一个名字包含另一个
（长度 ≥ 3），或两者最后 6 个字符相同（长度 ≥ 6），或两者属于同一个语义可替换族
（`{cup, mug}`、`{pot, pan}`、`{cloth, towel, handtowel}`、`{soapbar, soapbottle}`）。
在 v4 的 134 题上，这个判据给出 **35 题**（avg@3 0.6571）与其余 **99 题**
（0.8316），与事故分析里"易混题承担几乎全部残差"的结论一致。判据实现在
`tmp/v6_analysis.py`（`related()` 与 `synonym_prone()`）。

任一条不满足则 2b 不通过，先归因再决定是否改，不直接上 V6。

## 结果（2026-11-07 补记）

三条臂都是同一技能库、同一任务集、同一端点，只有 `playbook.md` 不同；三份 playbook
都由同一条写作提示词从同一份 P01 事实写出，审计全部干净（804/804、无 infra、
全部判分）：

| 臂 | playbook | 总体 avg@3 | 易混 35 题 | 其余 99 题 | 失败数 | 其中"从未取到物体" |
|---|---|---:|---:|---:|---:|---:|
| 2a 校准 | v5 文本 | 0.7761 | 0.5810 | 0.8451 | 90 | 29（32%） |
| 2b 候选 | v6b | 0.7836 | **0.6571** | 0.8283 | 87 | 43（49%） |
| 2c 候选 | v6c | **0.7065** | 0.5143 | 0.7744 | 118 | 58（49%） |

- 2b 对 2a：总体 +0.75pp [−3.73,+5.22]（14/14），易混 +7.62pp [−0.95,+16.19]（8/2），
  其余 −1.68pp [−6.73,+3.70]；**按预注册标准判定：不过**（易混绝对值 0.6571 <
  0.667、cool 的"从未取到物体"10 > 5）。
- 2c 对 2a：总体 **−6.97pp** [−12.44,−1.74]（11/26），关键损失在 pick_two
  （0.510→0.294）与 cool（0.730→0.651）。

## 归因：单次写作的抽样方差压过了提示词的改动

同一份事实、同一条提示词，连续写 5 次（`tmp/pb_var_1..5/`）：长度 5,204–8,579
字符，六项必需条款只在 1/5 的样本里全部出现。三份被评测的文本（v5、v6b、v6c）
同样来自"同一份事实 + 不同抽样"，总体分差达 **7.7pp**。

因此：

1. **门二这个设计在当前机制下无法归因**：它比较的是两份文本，而文本的抽样方差
   比要验证的效应大一个量级；
2. 之前几轮（v1–v5）基于单次文本的横向比较，同样可能被抽样方差污染；
3. 把写作温度改成 0 行不通：作者模型（reasoning effort max）会耗尽 65,536 token
   预算、返回空内容（`tmp/pb_greedy.log`），所以写作只能保持采样。

**结论：门二不通过，且不是文本内容的问题。** 在写作方差被控制之前，继续按
"改提示词 → 单次回放"迭代没有意义。

## 已知的端点差异（在门二之前就测到，记录在此以便判定时引用）

- 同一 92 道第一步 prompt，自建 vLLM（开思考）与 llmcenter 的**动作一致率 85%**
  （关思考只有 41%），因此采用开思考；
- vLLM 的 qwen3 reasoning parser 把思考拆进 `reasoning` 字段，而 ALFWorld 协议要求
  `<think>…</think>` 在正文里；客户端按 `EXPEDISTILL_LLM_THINK_IN_CONTENT` 把它接回，
  2,000 余条请求里 98% 走这条路径；
- 模型偶尔（约 2%）自己在正文里写 `<think>` 且漏掉 `</think>`，触发一次纠正请求：
  本 run 的纠正率约 7%（历史 llmcenter run 约 1.8%）。纠正不占用环境步数，属于
  已吸收的开销，但会在判定时作为已知差异记录。
