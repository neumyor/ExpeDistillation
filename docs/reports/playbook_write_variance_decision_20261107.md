# 可学习 playbook 的写作方差：A/B/C 三个方案的成本与取舍

日期：2026-11-07
这份文档是什么：门二失败后的决策说明——写作端的抽样方差有多大、三个候选方案各自
能解决什么、以及论文主表的测量口径该怎么定。对应 log.md 2026-11-07 04:00 条目。

## 一、问题

门二（受控回放：同库、同任务、同端点，只换 playbook 文本）测到三份文本的总体
avg@3 分别是 0.7761（v5）、0.7836（v6b）、0.7065（v6c），**差 7.7pp**。三份文本
由同一份 P01 事实、几乎同一条写作提示词写出，唯一变量是抽样。

同一份事实连写 5 次（不带结构校验）时：长度 5,204–8,579 字符，六项必需条款只有
**1/5** 的样本全部包含，被评测的 v6c 就属于缺条款的一类 → 写作方差比要验证的
效应大一个量级。

## 二、方案 A 落地后的实测（20 份，`tmp/pb20/`）

已实现：写作后按六个必需部分做机器校验（`## format` / `## recipes` /
`## search order` / `## object identity` / `## delivering` / `## prohibitions`，
其中 identity 还要求双向表述），缺项把缺的名字回给模型重写，最多 2 次；每次
尝试的缺项与字数记进 `playbook.json`。

| 指标 | 结果 |
|---|---|
| 六项条款全含 | **20/20**（对照：无校验时 1/5） |
| 首次通过 / 需一次重写 | 18 / 2（两次都是 object identity 的双向表述） |
| 长度 | 5,616 – 9,714 字符，中位 7,475（提示词目标 2,500–5,000，**全部超标**） |
| 两两 3-gram Jaccard | 0.094 – 0.236，中位 **0.154** |
| 参考：三份被评测文本两两 Jaccard | 0.079 – 0.106 |

**结论：A 只压结构轴，不压内容轴。** 条款齐全率从 20% 提到 100%，但长度分布与
文本相似度和不校验时没有区别（中位 Jaccard 仍在 0.15 量级，甚至比三份被评测
文本之间还"像"一点）。也就是说 A 能保证"不缺件"，不能保证"写了哪条规则、
按什么顺序搜、举哪个例子"——而 7.7pp 的分数差正是后一类差异造成的。

## 三、A / B / C 对照

| 方案 | 做法 | 成本 | 能解决 | 不能解决 |
|---|---|---|---|---|
| **A 结构校验**（已实现） | 六项条款机器校验，缺项重写 | 代码 1 小时 + 20 次写作约 40 分钟；正式 run 每次多 0–1 次写作调用（约 3 分钟） | 缺件的 playbook 不再进入执行；写作质量的下限抬高 | 内容轴的抽样方差（长度、规则取舍、例子选择）完全不变 |
| **B 多抽样报均值** | 同一份事实写 N 份，各自跑完整受控回放，报均值与区间 | 每份一次受控回放约 2.5–3 小时（64 并发）；N=3 串行 9 小时、两臂并行约 5 小时 | 把"这个机制到底值多少"测准；给出论文可写的方差估计 | 不降低单次 run 的方差；正式 run 仍是抽一次 |
| **C 按结果挑样本** | 用测试分数挑一份最好的文本 | 与 B 相同（要先跑完才能挑） | 数字最好看 | 属于按测试集选模型，**高估**；不能进论文 |

补充 D（未列入原选项，但成本最低）：**接受方差、只报单次 run**。成本 0，能解决
"现在就能跑 V6"，不能解决"这个数字可复现"——换一次写作就会变，审稿人问起
"重复一次是多少"没有答案。

## 四、对论文主表的建议

### 4.1 同一张表里的臂必须在同一端点测

端点切换的实测差是 **−3.73pp**（同一份文本、同一技能库、同一任务集：llmcenter
0.8134 vs 自建 vLLM 0.7761，95% CI [−7.71,−0.00]）。参考臂、手写 playbook 臂、
可学习 playbook 臂都是 `with_bank` 臂，如果有的在 llmcenter、有的在 vLLM，表内
差值就混进了端点差。两个可行口径：

1. **统一到自建 vLLM**：参考臂与手写臂各重跑一次终测（可复用已有技能库做
   `fork-run --through p06`，每臂约 3 小时，两臂并行约 3 小时），可学习臂用同一
   端点。代价：历史数字全部作废重测，收益：一张干净、可复现、不依赖第三方服务的表。
2. **统一到 llmcenter**：保持现状，但论文依赖一个我们在迁移的服务，且以后每加
   一个臂都要回到它上面测。

建议选 1。**冻结的外部对照臂（0.6269）来自历史 campaign，是 llmcenter 上的数**，
无论选哪个口径都要在表里显式标注它的来源，或者在新端点上重测一份裸跑对照。

### 4.2 可学习臂的数字怎么报

- 只跑一次：必须在正文或脚注写明"单次写作，换一次抽样结果会变"，并给出本文
  档测到的方差量级（同事实 20 次写作，长度 5.6k–9.7k；已评测的三份文本分差 7.7pp）；
- 跑三次（B）：报均值与区间，这是唯一能让"可学习 playbook 与手写 playbook 相当"
  这句话站得住的做法；
- 不要把 C 的结果写进论文。

### 4.3 建议的执行顺序

1. 两臂各写 3 份 playbook，各做一次受控回放（串行 64 并发，约 5 小时）：v5 臂从
   暂停 run 里冻结的 v5 期 prompt 重采样，v6 臂走当前机制；每份只跑 1 次采样
   （45 题 × 3 次 = 135 单元），这是诊断工具，不是论文口径；
2. 判定带平局带：设两臂均值差为 d（v6 − v5），|d| < 2.5pp 判"无可检测差异"并
   **保留 v5 机制**（A 的结构校验保留），d ≥ +2.5pp 保留 v6 方向，d ≤ −2.5pp
   回到 v5。平局带的依据是单份 134 题二项噪声约 4pp、3 份均值约 2.4pp；
3. 结论落地后，在**统一端点**上重测参考臂与手写臂，再起正式的论文臂 run——
   这一步等用户本人拍板。
