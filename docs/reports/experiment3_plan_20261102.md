## 假设

按适用时刻分段（设计一）让技能对应任务中途的时刻，学生才能在中途用上技能。操纵变量是
`phases.learn_add.review.K`：K=1 时每条轨迹只有一段（整条轨迹，起点是任务开始），
K=5 时最多 5 段（起点散布在任务中途）。其余配置完全相同。

代码事实：`K` 只被 P02（`learn_add`）的分段使用；后面的 `learn` / `learn_trial`
是 trial-level 审阅，不按 K 切段。因此这个消融检验的是**初始技能库的分段方式**；
后续相位两个臂都可以修订和新增技能。论文里应写成“初始写作的分段数”，不要写成整个
学习流程的单元数。

## 臂

| 臂 | 配置 | 说明 |
|---|---|---|
| K=5 | `configs/experiments/alfworld_split_paper_v2_e1_ours.yaml` | 参照方法，`learn_add.review.K = 5` |
| K=1 | `configs/experiments/alfworld_split_paper_v2_e3_k1.yaml` | 只把 `learn_add.review.K` 改为 1 |

两个臂都是：ALFWorld 39 训练 / 134 测试 ×3，教师 D、学生 Q，folder 交付，

不各跑裸对照。

## 预注册指标（先固定，后看结果）

数据来源全部是 run 目录里的程序事实，不调用裁判模型。

1. **avg@3 / pass@3**：134 个测试任务，条件口径 avg@3（每题先对有判分 trial 求平均，
   再对至少有一个有判分 trial 的题求平均）；pass@3 是至少一个成功 trial 的题占比。
   由 `paper_tables.load_arm` 重算并与 `phase_summary.json` 对齐，不一致即作废。
2. **技能库大小**：初始库取最早留下 `skill_bank.jsonl` 的学习相位（P02），最终库取
   最晚的学习相位（P06）。计数是 `skill_bank.jsonl` 的行数。
3. **不在任务开始适用的技能占比**：每个技能取 `source_subtasks` 指向的 Subtask 的
   `step_range[0]`（段的起点就是技能的适用时刻），merge 技能取所有来源的最早起点；
   id 规范化规则见 `segmentation_metrics.skill_origin`。`anchor == 0` 记为任务开始适用，
   `anchor > 0` 记为中途适用，解析不到记 unknown 并单独报告；分母是 anchor 可解析的
   技能数。初始库与最终库分别报告。
4. **任务中途打开率**：测试相位 with-bank 的每个 trial，按存储的步骤序列找第一个
   非 `ReadSkill[…]` 的环境动作；此后出现过至少一次读取即记为中途打开。分母是该臂的
   全部 with-bank trial。另报“任意打开率”（有读取即算）作为参照。按 trial 报告，
   不按题平均。

不新增其他口径，不按结果改分母。unknown anchor 不得被当成“任务开始适用”或
“中途适用”计入分子。

## 预期与判定

- **机制指标（主要依据）**：K=1 的“不在任务开始适用”应接近 0；K=5 应明显大于 0
  （旧 run 的构造检查是 0/10 对 8/13，但那是旧协议结果，只用来验证口径可算）。
  若 K=1 仍出现大量中途技能，说明后续相位把 K 的差异抹平了，设计一的检验不成立，
  论文不能声称分段决定了技能的适用时刻。
- **任务中途打开率**：K=5 应高于 K=1。旧口径检查只差约 5 个百分点，因此不要求大差距；
  若方向相反或持平，机制结论只能依赖 anchor 分布。
- **成功率（方向参考）**：134 题 ×3 的最小可分辨差约 4.5 个百分点；ALFWorld 学生
  成功率约 0.63（统一协议），提升空间比旧协议大，但仍不把小于 4.5 个点的差异写成
  “有效”。报告配对 95% 区间与胜负平，区间跨 0 时只写方向。

## 运行计划

1. 生成两个配置（`--stems e1_ours,e3_k1`），用生成器的 diff 确认只差 `learn_add.review.K`。
2. 顺序运行：先 K=5（参照），再 K=1；32 并发；每个 run 独立目录。
3. 每 30 分钟巡检；基础设施失败按原目录续跑，不改配置、不改协议。
4. 每个 run 完成后：`paper_tables.load_arm` 重算一致性、`infra_missing` 为空、
   with-bank trial 数 = 402（K=1 若有个别 invalid trial 单独记录）。有问题写
   `INVALID.md`，不进表。
5. 用 `segmentation-metrics --arm K=5=... --arm K=1=...` 生成表 3 的 ALFWorld 半边，
   写进 `docs/reports/segmentation_k1_k5_20261102.md`。

## 2026-11-02 修正：重读卡片的协议 bug（在看新结果之前）

第一次 K=5 run（`runs/exp3_k5_20261102_1931/`）跑完后发现 92% 的 trial 在中途
打开技能、63% 的 trial 读了 4 次以上，很多是同一张卡重复 30–48 次。原因不在技能
内容：旧读取策略在超过 3 张不同卡后对每次读取都回答“达到上限”并**占一个游戏步**，
模型拿不到正文就反复重读，把 50 步预算耗尽（`termination: step_budget`）。这个 run
已写 `INVALID.md`，进不了表；正在跑的 K=1 也已停止并标记作废。

修正（`benchmarks/alfworld/protocol.py`）：读取上限只约束**不同**的卡；已打开过的
卡重读会再次返回正文、不占新的卡片额度；前 `REPEAT_READ_FREE = 10` 次重读不占
游戏步，之后每次重读占一步（保证反复读同一张卡的序列仍会终止）。新的卡片超过上限
仍被拒绝，但拒绝不占步。两个臂都在这套策略下用全新 run 目录重跑。

第一次修正后重跑 K=5（`runs/exp3_k5_v2_20261102_2312/`），读取循环仍在：卡片只
存在于统一协议的 2 步历史里，一个动作后就被挤出 prompt，模型于是再次读取。
262/402（65%）的 trial 读了 4 张以上，153 个（38%）读了 11–100 次，这些 trial 平均
用掉 48.4/50 步。第二个修正：**已打开的卡一直留在 prompt 的 “Opened skill cards”
段落里直到 episode 结束**，重读只返回指向该段落的提示；前 10 次读取交互不占步、
之后每次占一步保证终止。该 run 同样写 `INVALID.md`，两个臂再次用全新目录重跑。

两次修正都发生在看到任何有效的 K=1 / K=5 正式结果之前；作废 run 的数字不参与
比较，也不用于挑参数。

## 2026-11-03 输出上限改为 65536

在 4096 的统一协议上限下，教师 D（reasoning effort max）的 baseline 执行回复有
571/2953（19.3%）被截断，纠错回复里又有 299/966（31%）被截断；学生 Q 的测试回复
只有 3/8134（0.04%）被截断。教师侧的截断会改变技能库学习所依赖的轨迹，因此把
ALFWorld 执行协议的输出上限改为 65536（配置级预算），两个臂都在 65536 下重跑；
`runs/exp3_k5_v3_20261103_0246`（4096）写 `SUPERSEDED.md`，不进表。

裸 D / 裸 Q 由另一个会话（“skill evolve 算法论文实验-裸跑结果”）产出，本实验
直接使用那边的裸跑结果作为对照，不再自己跑裸跑。在该结果文件就绪前，配置里仍
指向已冻结的裸 Q 文件；最终比较用对方的裸跑分数重算，不重复执行对照。

## 2026-11-03 第二次协议修正：读卡不占记忆槽位 + 部署约束写入 profile

检查 v4 结果时确认了两个结构问题（详见
`docs/decisions/deployment_constraints_and_read_slots_20261103.md`）：

1. 教师写技能时不知道学生执行期的记忆（当前观察 + 最近两对交互 + 已打开卡段落），
   写出的 `[Steps]` 常引用更早的步；现在 ALFWorld 配置启用
   `configs/profiles/alfworld_unified_memory_20261103.md`，由构造 profile 段的代码
   统一加上"profile 即约束"的绑定行。
2. `ReadSkill` 曾占用统一协议的两个记忆槽位之一（写进 2 步历史并替换当前观察）；
   现在读卡只记入 `steps` 供答卷分析，不进入历史、不替换观察，卡片正文常驻
   "Opened skill cards"，读卡结果由 "Last skill read" 一行报告；终止保证不变。

这两项改变执行协议与写作提示词，因此 v2 代的两个结果作废（保留为记录，不进表）：

- `runs/exp3_k5_v4_20261103_0957/`（K=5，avg@3 0.6393）写 `SUPERSEDED.md`；
- `runs/exp3_k1_reuse_20261103_1436/`（K=1，未跑完）写 `SUPERSEDED.md`。

baseline 相位不使用技能文件夹、也不调用写作，提示词逐字未变；两个臂都从
`runs/exp3_k5_v4_20261103_0957` 用 `assemble-reuse --level baseline` 复用 234 条
train 侧轨迹（117 强 + 117 弱），从 P02 起全新执行。预注册指标与判定规则不变。

## 不做什么

- 不复用旧协议的 e1_ours / e3_k1 数字（协议不同，已作废）。
- 不为两个臂各跑一份裸对照。
- 不在本实验里改方法 prompt、分段 prompt 或学习流程；K 是唯一变量。
