# e1 ours 的 prompt 层改进分析

基线：run `alfworld_paper_e1_ours_20261113_2006`（远程主机），终测 avg@3 0.7736 / pass@3 0.8657；
同口径裸跑 `alfworld_paper_e1_bare_q_20261113_2006` 0.6244 / 0.7687。两者审计干净，结果与口径见
`docs/reports/alfworld_e1_evidence_driven_20261115.md`。下文所有数字都来自这两个 run 的终测轨迹
（各 402 局），分析脚本与原始输出在远程 `tmp/fail_taxonomy.py`、`analysis/test_trials_20261115.json`。

## 一、失败在哪里

ours 失败 91 局，裸跑 151 局。按"最远推进到哪一步"分类：

| 失败阶段 | ours | 裸跑 |
|---|---:|---:|
| 从没拿到目标物 | 56 | 110 |
| 拿到了，状态变化（清洁 / 加热 / 冷却）没做 | 6 | 21 |
| 两物体任务只送到 1 件或 0 件 | 18 | 10 |
| 送到了但没判成功 | 9 | 6 |
| 其他 | 2 | 4 |

三个可以归因的失败来源：

**1. 两物体任务退步（0.61 → 0.31，17 题）是 playbook 规则造成的。** 第一次交付之前观察里已经
出现过第二件目标物的局：

| 臂 | 回去拿了 | 从没回去 |
|---|---|---|
| ours | 16 局，成功 13 | **13 局，成功 1** |
| 裸跑 | 25 局，成功 24 | 5 局，成功 1 |

ours 的 playbook（p06 版，6,421 字符）规定搜索"单向走，不准回到更早的种类或实例""不准重访
已打开且为空的位置"，两物体任务交付第一件后"按固定的两物体顺序继续"。学生守住了这些规则，
看到过的第二件就再也不回去拿。另有 12 局一件都没交付（裸跑 7 局）。

**2. 拿错物体（24 / 91 局失败，其中 12 局反复拿 3 次以上）。** 常见混淆是语义相近、名字不同的
物体：cup ↔ mug 7 局、cloth ↔ towel / handtowel 8 局、knife ↔ butterknife 3 局。playbook 的
"物体身份"一节只举了字面相近的例子（pot / potato、pen / pencil），没有覆盖这类日常说法里可互换、
在 ALFWorld 里却是两种物体的情况。拿错之后学生会在错的物体上反复加热、放下、再拿起。裸跑错拿
73 局，说明 playbook 已经减少了这类错误，但没有消除。

**3. 搜索覆盖不足（54 局从没看到目标物）。** 这些局用满 50 步，平均只到过房间里 52% 的位置，
每局重复"go to"已去过的位置 27 次。搜索卡 `type/001` 在相邻两次学习里都拿到正文证据，按规则
在 p06 被删除，最终库里没有搜索卡。

其他观察：

- **执行期格式错误**：ours 平均每局 2.6 次无效回复（失败局 6.4 次、成功局 1.6 次），兜底 `look`
  0.5 次；裸跑 4.9 次、2.5 次。playbook 的 format 一节已经起作用；
- **卡的使用**：终测 22% 的局打开过卡，集中在"拿起目标物"（55 局，成功 41）、加热（27 / 20）、
  冷却（11 / 9）。清洁（93 局里 16 局打开）、两物体、look 没有对应的卡；
- **练习与终测没有落差**：第二次练习（训练集、样本内）0.744，终测 0.774，看不出过拟合；
- **诊断**：第一次学习 49 条失败里 26 条判为通用问题（不产生卡证据），通用问题的笔记只进画像
  和 playbook。

## 二、改动候选（只改 prompt，不改架构）

| 编号 | 环节 | 改什么 | 证据 | 预期增益（avg@3） | 成本 | 风险 |
|---|---|---|---|---|---|---|
| **P1** | playbook 写作（`ALFWORLD_PLAYBOOK_UPDATE`） | 写作者必须保留"记住看到过的未拿目标物位置"的例外：搜索的单向与不重访规则不适用于已看到的目标物副本；两物体任务交付第一件后先回到记录过的副本位置 | 一 · 1 | +2 到 +4pp（两物体 17 题从 0.31 回到 0.5–0.6 的上限是 +3.8pp） | 一次完整 run | 写作者可能把"可以回去"泛化成反复回访，拉低其他类型的搜索效率 |
| **P2** | playbook 写作 | 物体身份一节要求写作者从本相位的诊断笔记里列出实际混淆过的名词对，并写明"名字不同即不是同一物体，即使日常可互换" | 一 · 2 | +1 到 +2pp | 同上 | 写作者只能列出训练集里出现过的对；测试集新的混淆对不受益 |
| P3 | 写卡与改正文（`CARD_WRITE` / `REVISE_CONTENT`） | 搜索类卡的正文要求按"已访问清单"推进、不重访，且写明何时允许回到看到过的目标物 | 一 · 3 | 0 到 +2pp，不确定 | 同上 | 搜索卡曾两轮改正文仍失败被删，prompt 改动未必扭转 |
| P4 | 执行期提示（统一 runner 模板） | 在模板里加一行格式提醒，减少无效回复 | 其他观察 | 约 +1pp | 需同时重跑裸跑对照（约 3 小时，只用本地 Q） | 改变统一协议，与已有的所有对照都不再同口径 |
| P5 | 画像与诊断 | 画像只给写作者看，诊断的范围判定影响证据分配 | — | 间接，无法单独估计 | — | 不建议单独做 |

P1、P2 的预期增益都小于单次 run 的比较噪声（见三），**单独一次 run 的差值不能判定它们有效**。

**P1 的实现定义（2026-11-15 定稿）**：不是"记住看到过的副本、回去拿"。ALFWorld 协议只给学生看
最近两步，`ALFWORLD_PLAYBOOK_UPDATE` 也要求每条规则能从当前观察、最近两步和物品栏核对，所以需要
记忆的规则学生无法执行；裸跑拿到第二件，多半是因为它绕圈子碰巧又走回去。P1 改为在写作提示词
里规定"两物体任务是两次搜索"：交付第一件、目的地只显示一件之后，第二次搜索从顺序的第一个种类
重来，单向、容器已搜完、种类已搜完三条规则随之重置，第一次搜索经过的地方重新允许访问。改动只在
写作提示词第 3 条（搜索规则）与第 5 条（交付规则），学出来的 playbook 由 D 照常生成，不手改。

## 三、噪声与判据

- 终测采样噪声：同一臂两次运行之差的 95% 范围约 ±6pp（按题拆半估计，`noise_floor`）；
- **学习过程本身也有方差**：playbook 与卡由 D 在 temperature 1.0 下写出，同一配置重跑会得到不同的
  playbook 与库。这部分方差目前没有测过，很可能大于采样噪声。所以 0.7736 本身也需要复跑一次才
  知道它的波动范围；
- 因此判据用两层：
  1. **机制判据（预注册，单 run 可判）**：P1 生效的标志是"第二件已看到却从没回去"的局数从 13
     降到 5 以下，且两物体任务 avg@3 ≥ 0.50；P2 生效的标志是终测失败局里拿错物体的局数从 24
     降到 12 以下；
  2. **总分判据**：与 e1 ours 按题配对，差值的 95% CI 下界 > 0 才算总分提高；只有机制判据满足
     而总分 CI 跨 0 时，报告为"机制起效、总分未分辨"，不宣称达到目标。

## 四、运行计划

保持不变的：执行温度 0.95、同一 vLLM 学生、同一复用摸底（`import-baseline`）、同一同口径裸跑
对照、同一配置（只换提示词，提示词 digest 进 manifest，所以每个变体都是新 run 目录）。

| 顺序 | run | 内容 | 用途 |
|---|---|---|---|
| 1 | `e1_ours` 复跑 | 与 0.7736 完全相同的配置与代码 | 量学习加采样的总方差；后续所有比较的第二个基线点 |
| 2 | `e1_p1` | 只加 P1 | 两物体机制判据 + 总分配对 |
| 3 | `e1_p1p2` | P1 + P2 | 物体身份机制判据 + 总分配对 |
| 4 | 最优变体复跑 | 第 2 或第 3 个 run 的配置 | 确认 |

- 第 1、2 个 run 可以同时跑（互不影响，D 走网关、Q 共用 vLLM，会稍慢）；第 3 个 run 等第 2 个的
  机制判据出来再定是否叠加；P3、P4 暂不做；
- **单个 run 的成本**（参照 0.7736 那次）：墙钟约 3 小时 45 分；D 输入约 139 万、输出约 624 万
  token（诊断、切段、归类、写卡、改写、playbook）；Q 约 1.7 万次调用，在本机 vLLM 上；
- **总成本**：4 个 run，约 2,500 万 D 输出 token；两两并行时墙钟约 8 到 10 小时；
- **能否到 0.82**：从 0.7736 到 0.82 需要 +4.6pp。P1 的上限约 +3.8pp，P2 约 +1 到 +2pp，合计
  有可能接近，但两项的预期都落在单 run 噪声以内，必须靠第 1 个基线复跑和第 4 个确认复跑才能
  判定，不能凭一次 run 宣布达到。

## 五、落盘

每个新 run 一个新目录，按现有规范完整性审计后写进远程 `RUNS.md` 与本地 log.md；e1 ours 的
run 目录与本报告引用的证据只读，不覆盖。提示词改动在本地改、测试、提交后再部署为新的代码目录。
