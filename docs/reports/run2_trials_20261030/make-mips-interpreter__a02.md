# make-mips-interpreter / attempt 2（失败）

- trial：`traj/tb:make-mips-interpreter/strong/02`；步数 53；读取的技能：无
- 主因：A_model_capability

## 1. 为什么失败 / 卡在哪里
- 卡点：第 47–50 步——解释器跑通了（打印出期望的 `I_InitGraphics: DOOM screen size: w x h: 320 x 200`，31,457,280 步后写出 640×400 的帧），但保存的是程序写出的第一帧；第 51–52 步提交。
- 过程：
  - 第 0–4 步勘查预编译二进制与源码树（`doomgeneric_img.c`、`my_stdlib.c`、`fake_fs.c`、链接 map），第 7 步用 `llvm-objdump` 反汇编；
  - 第 16 步统计出需要 `mul.s/bc1t/trunc.w.s/mfc1/mov.d` 等 FPU 指令；
  - 第 31–45 步依次修掉 `bad memory access 0x0`、自造语法错误、`andi/ori/xori/lui` 操作码错位；
  - 第 47 步把内存上限调大后，运行到 `W_Init`、启动 banner、`I_InitGraphics`，31.4M 步时打印 `OK first frame saved`，EXIT 0；
  - 第 48–50 步检查 BMP：宽 640、高 400，但 bpp 字段为 0；模型没有修程序侧，而是在 `vm.js` 写盘前把 bit-per-pixel 字段改成 32（第 50 步），断言 `BMP_OK`。
- 直接原因：两条失败断言分开看。`test_frame_bmp_similar_to_reference`（`Score: 0.7661, req: 0.95`）不受早杀机制影响：它比较的就是第 50 步最终产物写出的首帧，而该帧只比全黑帧的 0.7339 高约 0.03（标题画面尚未绘出），重跑多少次都一样；模型把"第一帧写出"当成结束条件，并且只用"非黑像素 > 10000"自证，没有检查帧内容是否符合任务要的画面——这是真实产出缺陷。`test_vm_execution` 的失败则受早杀影响：本 trial 的解释器确实会在 31,457,280 步后打印期望文本（第 47–50 步日志可见），但测试 1.072 s 内被残留 `frame.bmp` 提前放行，1 秒内到不了那一步。

## 2. 技能库里有没有能解决它的技能
- 候选：
  - `traj/tb:path-tracing/strong/00/seg01`（相关性 高）——"图像特征化 + 反汇编 + 逐像素验证复现输出"，与本 trial 的做法几乎一一对应；区别在于它要求最终逐像素对齐参考，而不是"非黑像素数量达标"。
  - `traj/tb:path-tracing/strong/00/seg00`（相关性 中）——先运行伴随可执行文件、比较其输出以确认关系。
  - `bank/merge/0001`（相关性 中）——基线/变体/评测循环与 exactness 验证。
  - `bank/merge/0004`（相关性 中）——提交前门禁：端到端行为与独立参考比对。
- 缺的能力：除了 MIPS 解释器本身，还缺"取帧时机/验收画面"的知识：应在标题画面完成渲染后取帧（或先按任务描述确认参考帧的内容），而不是第一帧。

## 3. 能解决问题的技能被触发了吗？为什么没解决
- 触发：没读。`meta.json` 的 `skills_read` 为空；轨迹里没有打开技能正文的动作，也没有出现 `<available_skills>` 清单。
- 原因：`path-tracing/seg01` 的触发条件（图像 + 不透明参考可执行文件 + 要复现输出）与本题高度吻合，是整库最接近的一张卡，但模型没有查技能文件夹。即便读了，它给的是验证方法（逐像素比对），仍需模型自己判断"哪一帧"是参考帧——所以这仍主要是能力/判断问题。

## 4. 结论与依据
- 主因：A_model_capability
- 一句话依据：相似度断言独立于早杀机制地失败（`Score: 0.7661`，首帧近黑；全黑帧为 0.7339），模型只验证了"非黑像素 > 10000"；`test_vm_execution` 的失败才由残留 `frame.bmp` 提前放行（1.072 s）造成，本 trial 的解释器在 31.4M 步后确实会打印期望文本。
- 次要因素：E——仅影响 `test_vm_execution`；D——库中缺"取帧时机/渲染验收"类技能。另有一处实现瑕疵：程序写出的 BMP 头 bpp 字段为 0，模型没有修解释器对结构体写内存的模拟，而是在写盘前硬改该字段（第 50 步）。
