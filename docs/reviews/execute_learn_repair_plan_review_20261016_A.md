## 逐项发现

### 【阻塞 A1】R3"比较归位"把 C 相位的 delta 搬进决策，违反边界 §3.9"测试结果不流进学习"

- **方案原文**（§4 R3）："**把 '带技能 vs 裸跑' 的计算从 `stages/stage6_test.py` 搬进决策**"；判据"`stage6_test.py` 不再计算 delta"。差距表 R3 的现状证据是 `stages/stage6_test.py:195 _delta`、`:330/:357 control_source`，并称"而边界文档 §3.1 说这归决策"。
- **边界原文**（§3.9）："**测试结果不流进学习**。C 阶段的报告只进入最终成绩，'带技能库比裸跑提升多少'由最终汇总计算，**不经过决策**。"边界 §3.1 说"决策负责比较：**本轮**结果比裸跑有没有提升"，指的仅是训练集上的学习比较；边界从未说 C 相位的 delta 归决策，反而在 §3.9 明文排除。
- **为什么是阻塞**：stage6 就是 C 相位（最终测试）。按 R3 的字面与判据实现，C 的结果就流经了决策入口，直接违反九条关键分工的第 9 条；而且**方案全文没有一处复述 §3.9**，实现代理只读方案不会知道这条约束的存在。方案的冲突裁决条款（"边界文档胜出"）救不了没有被告知的约束。
- **修法建议**：R3 改写为两条：(1) 学习比较（A/B 相位 vs 对照）归决策入口 `(本轮报告, 对照报告, 库, 剩余次数) → 任务清单`；(2) C 相位的 delta 由**最终汇总/相位驱动**计算，可以复用决策层抽出的同一套比较纯函数，但**不经过决策入口、不产生任务清单**。同时把 §3.9 原文一句话复述进 R3 或 §3 硬约束，判据改为"决策入口不得接受 C 相位报告作输入"。

### 【阻塞 A2】边界 §4.3 三条配套规则整体缺失；R6 判据与 §4.3.2 直接矛盾；§3.2.7 与 §4.3.1 相互顶死

- **边界原文**（§4.3）：1. 没变的单元不重测（题和注入的技能都没变 → 沿用上次验收结果；**改写后一字不差也算没变**；C 例外）；2. **改写失败就原样保留**（没产出新版本 → 视为没变 → 不重测，等下次学习再改，最后一次学习仍没提升才按表删除）；3. 裸跑全对可跳过带技能运行（严格规则时，标注"未跑：对照已全对"，决策据此得"无提升空间"）。
- **方案现状**：三条在方案全文中零出现。更糟的是两处正面冲突：
  - **R6 判据**（§4）："改写预算耗尽仍按'版本不变、本轮消耗、**下轮重答同版**'"——这是现行 E8 语义（下个 A 相位重新作答同版本），与 §4.3.2"**不重测**、沿用上次验收结果"直接矛盾。按方案判据实现会把边界明确取消的重测钉回去。
  - **§3.2 硬约束第 7 条**："跳过键 = 现行续跑键，**不新增'版本判断'机制**"。而 §4.3.1 要求"题和注入的技能都没变（含内容一字不差）就沿用上次验收"——现行续跑键（带技能作答 = (skill, version, 轮键)）做不到这一点，判定"没变"恰恰需要新的内容比较。硬约束按字面执行会让 §4.3.1 无法实现。
  - **no-op guard 未处理**：现行 live 语义是"改写成功但注入块与冻结行逐字节相同 → 不跑下一轮、**直接淘汰**（LIVE_NO_IMPROVEMENT）"；按边界 §4.3.1/4.3.2 应改为"视为没变 → 保留、不重测，末次学习仍没提升才删除"。这是一处边界强制的行为变化，方案未点名；而 R1 的判据"现有 no-op 场景全部通过"与 §3.3 的"E2 全覆盖 / E1–E6 对基线等价"会与该行为变化互相打架，方案也没有像旧方案 §6 那样列出"有意变化清单"。
- **修法建议**：(1) 在 R3（或新增 R3b）里完整搬运 §4.3 三条，删掉 R6 判据里"下轮重答同版"的表述或改写为"版本不变 → 不重测、沿用上次验收，等下次学习再改"；(2) §3.2.7 加但书："……不新增版本判断机制，**但边界 §4.3.1 的'没变不重测'是显式新语义，其判定键单独定义**"；(3) 把 no-op 处置变化、weak_already_knows 从"验收内立即终态"改为"跳过运行 + 决策得无提升空间"列为需披露的行为变化，并给出对应的 E2/E6 期望差异。

### 【偏移约束 P1】两套编号错位且开头声明为假，C2 的"R1/R6"按修复项编号读会指错人

- **修法建议**：给两套编号一张对照表（或统一改编号），删掉"编号即修复项编号"的说法；C2/C1 里的编号标注"（差距表编号）"；改正 14 项/四波两处计数。

### 【偏移约束 P2】Wave 0 的判据自相矛盾：C5 词汇变更与"golden 逐字节无 diff"不能同时成立

- §5 Wave 0 的判据是波级的："`pytest` 全绿 + **golden 逐字节无 diff**（这一步只搬不改，任何 diff 都是错）"，而同一波的工作含 C5 裁决（`RunOutcome.status` → `correctness: Optional[bool]` + 指标，§7 自己说波及 24 处 `.status ==`、12 个文件，且 Wave 0 的独占文件清单里有 `benchmarks/base.py`）。状态词汇一改，落盘的 Trajectory/status 值必然变，golden 必然 diff——"任何 diff 都是错"与 C5 在同一波内互相否定，实现代理要么违判据、要么违裁决。R0 正文里"这一步的判据"只挂在机械拆分那一条，与 §5 的波级判据口径不一。
- **修法建议**：Wave 0 内部切成两个提交、两套判据：机械拆分提交 = golden 逐字节无 diff；C5/词汇提交 = 单独判据（改哪些消费者、哪些 golden 字段预期变化）。§5 的 Wave 0 判据相应改写。

### 【偏移约束 P3】验收驱动在注册表五族之外，"methods/acceptance/ 换为新契约"与"注册表只留五族"互相矛盾

- **修法建议**：裁决清楚二者之一——(a) 边界下验收不再有"按方法可替换的驱动"（判定规则按 benchmark 具名，编排在相位驱动），`methods/acceptance/` 整目录删除，其内容并进 composites/benchmark 插件；(b) 保留验收驱动并在 R8 的族清单里加 `acceptance`。现在的写法两头都占。

### 【偏移约束 P5】R0 四形状的两处字段问题：单元级"终态"在多有效运行下语义未定；RunRecord 没有"参考答案作为附带信息"的通道

- **AcceptanceReport**（R0）："每单元一行……终态(成功/失败/无效/**测不了**+原因)"。边界 §2.3 对单元级只要求"有效运行几次，其中成功几次"＋无有效运行的"测不了+原因"；方案把逐次三值判定升格成了单元级终态，但 B 相位一单元跑 n 次、2/3 有效运行成功时，单元"终态"是成功还是失败没有定义。决策按 §4.1 拿"成功率严格提高"比较，用的是有效数/成功数，这个新造的"终态"字段语义悬空——而 W1-A 的第一件事就是把它广播给其余五个代理，悬空语义会传染。
- **RunRecord**（R0）：字段是"哪道题、注入技能、谁做、第几次、correctness、指标、轨迹与产物位置"。边界 §3.5 的考试归属表明确要求作答时"'对不对'留空，**参考答案作为附带信息传下去**"（判卷在验收，需要参考答案随记录可达）。R0 的 RunRecord 没有这条通道——判卷要么重新读题库对象，要么记录里就该有附带信息槽。方案作为"冻结接口"的文档应当写明。
- **修法建议**：AcceptanceReport 的"终态"限定为"无有效运行 → 测不了+原因"，单元级成绩只用"有效数/成功数"（与边界 §2.3 逐字对齐）；RunRecord 补一句"benchmark 附带信息（如考题参考答案）随记录可达，供验收判卷"。

### 【偏移约束 P6】R2/C5 引发的重试重分布是已知行为变化，未列入披露清单

- 现状：`benchmarks/tb/plugin.py` 的 `classify_result` 把 tmux 报错、模型异常等归 `infra_error`，`composites/batch_execute.py:354` 据此**机械重试**。边界 §2.2 要求"只要拿到了结果，不管看起来多可疑，执行都不重试"——这类"结果型错误"以后不再触发执行内重试，而是交验收判无效、由阶段调度重派（重派有上限、无效不计分母）。R2 的文字本身与边界一致，但这个重试从执行层移到调度层的**行为重分布**（模型调用次数账目、E4/E5 的期望）方案没有像旧方案 §6 那样逐处列为"有意变化"，只笼统说"除已披露差异外不变"——"已披露"在哪里没有交代。
- **修法建议**：在 §3.3 或 R2 下加一小节"已知行为变化清单"：infra_error 重试重分布、no-op 处置变化（A2）、weak_already_knows 机制变化，各配一句 E2/E4/E5 期望差异。这也符合本仓库 AGENTS"先注册、再看结果"的纪律。
