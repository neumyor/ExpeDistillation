## 1. 基本概念

### 1.1 闭环

整个系统是一个闭环：**轨迹 → 技能库 → 把技能库交给模型去做题，得到新轨迹 → 根据新轨迹更新技能库 → ……**

闭环只有两种阶段：

- **执行阶段**：技能库 + 任务 + 模型 → 运行记录 + 验收报告
- **学习阶段**：验收报告 + 运行记录 + 旧技能库 → 新技能库

一种方法就是这两种阶段排成的一个序列。例如 exam 方法是 `D L A L A L A L C`，live-run 方法是 `D L B L B L C`。其中 L 是学习阶段，D、A、B、C 是四种执行阶段，见 1.3。

### 1.2 两个阶段，七个模块

```
执行阶段：技能库 → 交付 → 执行 → 验收 → 验收报告
学习阶段：验收报告 → 决策 → 找证据 → 写作 → 整理 → 新技能库
```

- 执行阶段包含三个模块：**交付、执行、验收**；
- 学习阶段包含四个模块：**决策、找证据、写作、整理**。

阶段之间只传三样东西：**技能库、运行记录、验收报告**。执行单元清单、任务清单、证据包这些中间产物只在阶段内部流转，不跨阶段。

### 1.3 执行单元与运行记录

**执行单元 = 一道题 + 给它注入的技能。** 技能可以是一条、几条，也可以一条都不注入。由谁来做、做几次，是执行阶段的设置，不属于单元本身。

单元每被执行一次，就留下一条**运行记录**。

| 执行阶段 | 题 | 注入的技能 | 谁做、做几次 |
|---|---|---|---|
| D 摸底 | 每个训练任务 | 不注入 | 强、弱模型各做若干次 |
| A 纸面验收 | 每条技能对应的考题 | 这一条技能 | 弱模型答 1 次 |
| B 实战验收 | 每个有技能的训练任务 | 该任务的整包技能 | 弱模型做 n 次 |
| C 最终测试 | 每个测试任务 | 检索出的若干条，或整个技能库 | 弱模型做 n 次 |

**对照单元**指同一道题、不注入任何技能的单元。它可以在本阶段现场跑，也可以借用更早阶段（如 D）的结果。

## 2. 七个模块的边界

### 2.1 交付

**职责**：决定每道题注入哪些技能。

**输入**：技能库；本阶段要做的题。

**输出**：执行单元清单。每一行是“一道题 + 注入的技能”，技能可以为空。

**边界**：交付只回答“每道题给什么技能”，不看任何历史结果，也不关心题怎么跑。不注入、每条技能单独注入、按任务整包注入、检索 top-k、整库注入，都是交付的不同方式，彼此可以替换。

### 2.2 执行

**职责**：适配不同的 benchmark，把各 benchmark 的运行结果统一成同一种输出格式。

**输入**：执行单元清单。

**输出**：每次运行一条运行记录，包含：

- 这次运行是哪道题、注入了哪些技能、谁做的、第几次；
- **对不对**：benchmark 自带的判分器或标准答案给出的结果。benchmark 没有判分器或标准答案时，这一项**留空**；
- **运行指标**：重试次数、每次报错的原文、耗时、退出状态等；
- 轨迹和其他产物（最终答案、生成的文件等）的存放位置。

**边界**：执行只负责“跑”和“记录”，不做任何判定，也不解释失败原因。这次运行算不算正常完成、为什么失败，都不由执行回答。

执行内部只做**机械重试**：runner 没有交回任何结果（抛出异常、进程崩溃、连接失败）时就重跑，直到拿到结果或次数用完。只要拿到了结果，不管看起来多可疑，执行都不重试，原样交给验收。

### 2.3 验收

**职责**：对每次运行给出最终判定。

**输入**：运行记录，以及记录指向的轨迹和产物。

**输出**：验收报告，包含：

- **每次运行的判定**：成功、失败（模型做错了）或无效（运行没有正常完成，不能算作模型的成绩），并附判定依据；
- **每个单元的汇总**：有效运行几次，其中成功几次；没有任何有效运行的单元报为“测不了”，并写明原因；
- 每个单元注入了哪些技能；
- 轨迹和产物的位置。

**边界**：验收只回答“这次跑成没成”，是绝对判定，不和对照比较，也不决定怎么处理技能。

执行给出了明确的对错时，验收以它为依据，但最终判定仍由验收做出。执行留空的，由验收自己判定，例如由模型对照参考答案判卷，或由模型读轨迹打分（心理辅导这类没有判分器的 benchmark）。

“什么样的运行算无效”属于验收，比如沙箱崩溃、断网、超时、泄题。判定规则按 benchmark 区分，做成具名规则；和某个 benchmark 绑定的判断逻辑放在该 benchmark 的插件里。

被判为无效的单元，由阶段调度重新派给执行，重派次数有上限；用完上限仍无效的单元，就留作空缺。

### 2.4 决策

**职责**：决定本轮技能库要做哪些操作。它是学习阶段的核心。

**输入**：

- 本轮的验收报告；
- 对照的验收报告（裸跑结果），由阶段配置指定取自哪个阶段；
- 当前技能库；
- 后面还剩几次检验。

比较规则是决策的参数，例如“成功率严格提高”。

**输出**：任务清单。每个单元对应一个动作：**保留、修改、删除（附原因）或新增**。

**边界**：“有没有提升”这一步归决策：决策拿本轮的单元汇总和对照汇总比较，得出结论，再按第 4 节的规则定动作。

决策不读轨迹，只读报告。它也不决定具体怎么改，只决定对哪个单元做什么操作。动作的作用对象和测量的单元一致：纸面验收是一条技能，实战验收是一个任务的整包技能。

### 2.5 找证据

**职责**：按任务清单收集写作需要的信息，并整理成统一格式。

**输入**：任务清单；验收报告里指向的轨迹和产物。

**输出**：证据包，格式统一：

- **修改时**：旧技能，哪里出了问题，相关的轨迹片段或答卷；
- **新增时**：要从哪几段经验里学。

**边界**：找证据只报告事实，不决定动作。比如它可以报告“第 5 步照着 s2 做走错了，s3 没被用上”，但不说“所以删掉 s3”。从轨迹中切出值得学的段落、读判卷说明、分析包里哪条技能出了问题，都是找证据的不同做法，产出的证据包格式相同。

### 2.6 写作

**职责**：按预定的写作规范新建或修改技能。

**输入**：任务清单；证据包。

**输出**：新建的技能，或修改后的技能（版本号加一）。

**边界**：写作只依据证据包落笔，不管证据来自考试还是实战，也不做任何测量。对一个整包执行“修改”时，具体重写哪条、去掉哪条、补哪条新的，由写作根据证据决定。

### 2.7 整理

**职责**：把技能整理成最终形态的技能库。

**输入**：本轮的技能，即旧库去掉删除的、换上修改后的、加上新增的。

**输出**：新技能库。

**边界**：整理只做合并、归类、控制总长度，不重新判定技能是否有效（那是验收和决策的事）。整理方式可以替换：agentbrew 带合并检查参数，`exam` 表示用 A 阶段的考题检验合并结果，`none` 表示直接接受；none 方法不做整理、原样入库。

## 3. 关键分工

1. **判定和比较分开**。验收只给绝对判定：每次运行成功、失败还是无效。决策负责比较：本轮结果比裸跑有没有提升。比较规则是决策的参数，不是验收的参数。

2. **执行不判定**。执行只把 benchmark 自带的判分结果原样传下去，没有就留空，并附上重试次数、报错原文等指标。运行算不算正常完成、失败的原因，都由验收判定。

3. **重试分两层**。执行只在没拿到结果时机械重试，不看失败原因。验收把运行判为无效后，由阶段调度把单元重派给执行，有次数上限。无效运行不计入分母，既不算成功也不算失败。

4. **需要模型来判的东西都归验收**，包括判卷、泄题检查，以及没有判分器、要靠模型读轨迹打分的场景。

5. **考试也是一种 benchmark**，只是题目现场出、没有判分器：

   | 步骤 | 归属 |
   |---|---|
   | 出题（附参考答案） | 执行：相当于准备题目 |
   | 作答 | 执行：“对不对”留空，参考答案作为附带信息传下去 |
   | 判卷 | 验收 |
   | 泄题检查 | 验收：泄题则这次测量无效 |

6. **报告只记录“注入了哪些技能”**。模型实际按哪条技能做的，要读轨迹才知道，属于找证据的工作。

7. **决策不读轨迹，找证据不定动作，写作不做测量**。三者之间只通过任务清单和证据包交接。

8. **实战验收的结论只到“包”**。B 阶段同一个任务的整包技能一起上场，结论只能针对整包，决策只能对整包定动作。包里哪条有问题由找证据查出事实，具体怎么改由写作决定。

9. **测试结果不流进学习**。C 阶段的报告只进入最终成绩，“带技能库比裸跑提升多少”由最终汇总计算，不经过决策。

## 4. 当前默认的决策规则

### 4.1 先比较，得出结论

决策拿本轮的单元汇总和对照汇总，按比较规则（默认是“成功率严格提高”）比较，每个单元得出下列结论之一：

- **提升**：本轮成绩按比较规则优于对照；
- **没提升**：本轮成绩不优于对照；
- **无提升空间**：对照（裸跑）本来就全对，带技能也不可能更好；
- **测不了**：没有有效运行，原因可能是泄题、注入过长、出题失败、无效重派用尽等。

### 4.2 再按结论定动作

| 结论 | 后面还有检验 | 后面没有检验 |
|---|---|---|
| 提升 | 保留 | 保留 |
| 没提升 | 修改 | 删除 |
| 无提升空间 | 删除 | 删除 |
| 测不了：泄题 | 修改 | 删除 |
| 测不了：其他原因 | 删除 | 删除 |
| 摸底：弱模型做不好、且还没有技能的任务 | 新增 | 新增 |

- **“后面还有检验”**：序列里这次学习之后还有没有在训练集上做的验收阶段（A 或 B）。最终测试 C 不算。
- **“摸底”那一行**：读 D 阶段的报告，按挑题规则判断哪些任务弱模型做不好。

### 4.3 配套规则

1. **没变的单元不重测**。题和注入的技能都没变的单元，沿用上一次的验收结果，不再重新执行。修改后内容和原来一字不差，也算没变。最终测试 C 例外，每次都重新跑。
2. **改写失败就原样保留**。修改没有产出新版本，就视为没变：按上一条不重测，等下次学习再试着改；到最后一次学习仍没有提升，就按表删除。
3. **裸跑全对时可以跳过带技能的运行**。比较规则是“严格提高”时，对照已经全对的单元，不可能得出“提升”，执行阶段可以不跑带技能的那次，报告中如实标注“未跑：对照已全对”，决策据此得出“无提升空间”。这只省调用次数，不改变任何结论；换成其他比较规则时，这条规则不适用。
