# 决定：skill_read_suffix 的选卡时机、读后复述与完成门

## 背景

P07 的 trial 级分析（`docs/reports/phaseformer_tb21_p07_trial_analysis_20261030.md`）里有三类
与技能使用有关的失败：

- `skill_present_not_read`：有适用的技能却没打开。106/117 个 trial 在第一批命令里就打开了一张卡，
  其中 54 个与 `ls`、`find` 等探测命令挤在同一批发出；此时模型还没看过工作区，只能凭目录里的
  一行描述选卡，常常选成最“通用”的一张。
- `skill_read_not_followed`：读了卡，但卡里的验证步骤没有变成动作。屏幕上已经出现失败信号
  （没有预期输出、对手胜率为 0），仍然标记完成。
- 覆盖为 `none` 的题被强制先读一张无关的卡。原因是旧文本写着“必须至少读一张，即使任务看起来很简单”。

## 决定

只改 `TencentSkillTerminus2.skill_read_suffix` 的默认值，三处：

1. **两阶段选卡**：先看一次工作区，再从 `<available_skills>` 里最多选两张“when to use”与所见匹配
   的卡；没有匹配就一句话说明并继续，不必打开任何卡。去掉“必须读至少一张”。
2. **读后复述一行**：读完一张卡后，在行动之前写一行：卡里哪个编号的步骤适用于当前任务、它的
   完成检查是什么。
3. **完成前自检门**：宣告完成前，逐一确认任务命名的输出路径存在；重跑能证明成功条件的检查并读它的
   输出，输出显示失败、错误或没有预期结果就不算完成；评分器会再次运行的交付物（脚本、宏、
   Makefile）要在干净副本上重跑并比较。

原有的 Shell hygiene 与 Graded thresholds 两节不变。文本通用，不含任何已见任务的具体内容。

## 事实核对

- **这段文本不在 system prompt 里**：它被拼在用户消息里，位于任务描述之后、终端状态之前
  （冒烟中为第 3680 个字符，消息总长 20077）。vendor 代码是
  `instruction + "\n\n" + suffix`。所以它的权重是“任务描述后紧跟的一段指令”，不是系统级。
- **名字**：仓库与 vendor 里没有 `skill_read_prefix`，实际参数是 `skill_read_suffix`。
- 新文本 2013 字符、15 个换行，sha256
  `360282525f87cab814311221bc2664628187951109fb006b196a4e5197c10ca9`。
- vendor 文件 sha256 前 16 位 `f21c45e9bacff379`，基准主机上的副本与本地镜像字节相同；
  备份在同目录 `tencent_sandbox_terminus.py.bak_20261030`（基准主机）与
  `tencent_sandbox_terminus.py.bak_20261030_local`（本地）。
- 只替换默认值，其前后代码逐行不变（先在本地副本演练验证）。

## 验证

用 P07 实际交付的技能文件夹（17 条，指纹 `bank:3bb3ee40d638`）在文件夹模式下跑一个真实 trial
（`sanitize-git-repo`），读取该 trial 的 `trajectory.json` 第 0 步，核对 9 项：技能模式生效、
新标题、“最多两张”、旧强制句消失、复述规则、两节旧规则保留、完成门、“干净副本重跑”。全部通过。

第一次冒烟无效：脚本没有给任务挂上 `skill_folder` 与 `skill_folder_dir`，插件走了裸模式，
vendor 的 suffix 根本没有被拼进去；因此那次的 7 项失败是脚本造成的，旧强制句“消失”也是
假通过。已改成复用 P07 的技能文件夹重跑。

这次 trial 16 步、`reward 0.0`，模型没有打开任何技能卡：新规则允许“没有匹配就不读”，
这是行为确实变了的证据，但单个样本不能说明变好。

## 后果与注意

- **这是行为变更**，按“改一个字也是新实验”，用新文本的运行必须新建 run 目录，不能与
  `tb21_p02p06_exam_small20_node2_20261029` 的 P07 合并成同一个 run。对照的最小做法是：复用
  P01 到 P06 的产物与交付库 `bank:3bb3ee40d638`，只重跑 P07。
- 这段文本**仍不在 manifest 的 `prompt_digests` 里**（它属于 vendor 代码）。新 run 的来源记录要
  手工引用上面的 sha256。
- 它只影响远程真实执行（live、test）；P03/P05 的纸面考试走本地 LLM 调用，不经过这里。
- 不处理的问题：技能库本身的覆盖缺口（电路综合、差分密码分析、MIPS 解释器、ReLU 权重恢复、
  视频帧检测）、目录里放触发线索、技能内容里的完成门槛段与模拟评分步骤；这些按用户决定不在
  这一轮改动。
