## 背景：实验三检查中发现的同一个根因的两面

2026-11-03 检查实验三（K=5 对 K=1）时发现两个问题，都是"学生执行时的上下文"没有进入
上下游的正确位置。

### 1. 教师写技能时不知道学生执行时的记忆

统一协议的学生每一步只看到三样东西：当前观察、最近两对（观察, 动作）、以及技能文件夹
循环维护的 "Opened skill cards" 段落。但写技能的教师看到的是完整轨迹视图，写出的
`[Steps]` 经常引用更早的步（"你刚才看到的物体"、"按第 2 步确定的房间"），学生执行时
这些信息早已离开上下文。这不是技能内容的质量问题，而是写作时缺少部署事实。

### 2. 读卡占用了统一协议的两个记忆槽位

旧实现把 `ReadSkill[...]` 当作一次交互写进 2 步历史，并把卡片正文设为下一步的
`current_observation`。统一协议的整个记忆只有两个槽位，打开一张最终用不上的卡就会把
真实的环境历史挤掉一一对弱模型来说，打开技能的代价因此远大于"多一次调用"。读卡
本来就不是游戏动作，不应参与协议的记忆记账。

## 决定

### 1. 部署约束写进 profile 并启用

- 新增 `configs/profiles/alfworld_unified_memory_20261103.md`：逐条写明读者在每一步的
  完整上下文（当前观察、最近两对交互、已打开卡段落）、它看不到的东西（初始房间描述、
  更早的交互、未打开的卡），以及由此产生的写作规则（不得按位置引用更早的步；需要事实
  时必须在同一节点里重新观察；卡片正文里的事实可以在卡打开期间持续使用）。
- `scripts/run/build_paper_configs.py` 对每个 ALFWorld 配置写
  `use_weak_profile: true` 与 `weak_profile_file: ../profiles/alfworld_unified_memory_20261103.md`；
  其他 benchmark 保持关闭、不传 profile。
- `prompts/profile.py` 的 `profile_section` 在非空 profile 后追加一条固定绑定行：
  profile 里陈述的一切（能力边界或执行期上下文）都是对所写每个节点的约束，
  依赖"读者那时没有的信息"的过程即使单个动作都在能力范围内也是缺陷。这一处覆盖全部
  写作/改写提示词（SKILL_DISTILL / SKILL_DIAGNOSE / REWRITE / CLUSTER_SKILL /
  REQUIREMENT_SKILL / 归因与 trial review），新增提示词不会漏掉约束。

### 2. 读卡不占用协议槽位

`benchmarks/alfworld/protocol.py` 的读卡分支改为：

- 读卡仍记入 `steps`（答卷与技能使用分析需要这条事实），但不写进 2 步历史、
  不替换 `current_observation`；
- 卡片正文只放在常驻的 "Opened skill cards" 段落；新增一行
  "Last skill read: ..." 报告最近一次读卡的结果（打开成功 / 已打开 / 超限 / 位置不存在），
  下一次游戏动作后清除；
- 终止保证不变：前 `REPEAT_READ_FREE = 10` 次重复或拒绝读取不占步，之后每次占一步，
  病态循环仍会在步数预算内结束；
- 位置写错不再消耗一张"不同卡"的额度（它不是卡片），按重复读取计费。

### 3. 配置代际与复用

- ALFWorld 配置文件进入 v3 代（`alfworld_split_paper_v3_*`）：v2 是 2026-11-02 统一协议
  对齐那一代，v3 是本次"部署约束 + 读卡不占槽位"。旧文件留在磁盘上作为记录，
  `--check` 不再把它们算作过期。
- 裸跑臂与 baseline 相位不经过技能文件夹、也不经过写作提示词，执行的提示词逐字未变，
  因此基线轨迹仍然有效：两个实验三臂都用 `assemble-reuse --level baseline` 从
  `runs/exp3_k5_v4_20261103_0957` 复用 234 条 train 侧轨迹，从 P02 起全新执行。
- `runs/exp3_k5_v4_20261103_0957`（K=5）与 `runs/exp3_k1_reuse_20261103_1436`（K=1，
  未跑完）在 v2 读卡策略下有效，但与本代不可比，写 `SUPERSEDED.md`，不进表。

## 不改的部分

- 统一协议本身的系统消息、无历史模板、历史模板、纠错请求、温度 / seed / 输出上限
  全部不变；裸跑臂的 prompt 与统一 runner 仍逐字一致。
- 分段、聚类、审阅、考试、判卷的方法逻辑不变；K 仍是实验三的唯一变量。
- 冻结的裸跑对照文件不变（裸跑没有技能文件夹，不触发读卡；也没有写作调用）。
