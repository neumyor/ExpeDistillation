## 背景

论文的第二个主张是：渐进式披露下，强模型写的触发条件在弱模型上常常失效，需要在技能演化的
循环里修正。这个主张要在三个 benchmark 上都能度量，而技能文件夹交付（`folder`、
`folder_by_task`）此前只有 TB 的插件支持。ALFWorld 与 SearchQA 只有整块注入（`skills_block`），
没有"只给目录、按需读取"的通道，实验四在这两个基准上无法进行。

约束（用户 2026-10-30 决定）：评测环境取自外层 `benchmark/alfworld-eval` 与
`benchmark/searchqa-eval`，本仓库只做接入它们的插件，不开发新的评测环境。

## 候选方案

| 方案 | 结论 |
|---|---|
| 在共用 ReAct 循环里响应读取动作，插件只选提示词并声明能力 | 采用 |
| 在两个环境适配器（`env.py`）里加读取动作 | 不采用。读取动作会进入游戏本身：ALFWorld 的"连续相同动作终止回合"规则与可用命令集都会误伤读取，适配器也要各写一份 |
| 把读取写成 `cat <路径>`，沿用 TB 的动作形态 | 不采用。两个本地环境没有 shell，`cat` 与它们的动作集冲突，模型容易混淆 |

## 决定

1. **动作与目录。** 提示词只含 `<available_skills>` 目录：名称、描述、位置，XML 形状与
   Terminus 一致，内容读自物化文件的 YAML 头。模型回复 `ReadSkill[<位置>]`（也接受前缀
   `> `、带引号、`./` 前缀和只写目录名）时，循环返回整份 `SKILL.md`，与 TB 里 `cat` 的输出
   相同。
2. **读取不占环境步数。** 一次尝试最多打开 3 张卡（`MAX_READS`，提示词里写明，属协议常量，
   改它等于新实验）。超出上限的读取被拒绝并占一步；位置写错得到报错观察并占一次额度。
   两种情形都保证只会读取的回复序列最终耗尽预算，不会停住回合。
3. **技能卡正文不被截断。** 后续提示的历史里，读取步的观察不经 `ViewRules` 截断；其他观察
   照常截断。存储的步骤保留完整原文。
4. **提示词。** `SEARCHQA_TASK_PROMPT_FOLDER`、`ALFWORLD_TASK_PROMPT_FOLDER` 由基础提示词
   派生，只多出读取动作和一段使用规则：卡片可选，描述与当前情境匹配才打开，任何一步都可以
   打开。不含"必须至少读一张"这类强制读取的措辞（P07 分析显示它会逼模型在没有对应技能
   的任务上读无关卡）。基础提示词字节不变。
5. **读取事实。** `RunOutcome.meta` 带 `skill_list_shown` 与 `skill_reads`，`steps_used`
   只计环境步数。`skill_use` 把 `ReadSkill[...]` 与 `cat` 同等看待，读取集、归因窗口、
   trial 级审阅因此不用改。`skill_usage` 据 `skill_list_shown` 把零读取的尝试判为
   "已交付、未读"；TB 存储的步骤不含初始提示，零读取仍是"未验证"。这一点对实验四的触发
   召回很关键：本地基准上可以直接数出"目录展示了但没有被打开"的尝试。
6. **接入点。** 两个插件声明 `skill_folder_prompt_name`，既有的能力检查、物化、任务挂载、
   `real_folder` 与 `folder_by_task` 全部沿用；阶段驱动与交付代码没有改动。

## 与 TB 的差异（解读结果时要带上）

- TB 的一次读取占一步且没有次数上限，本地读取免费但最多 3 次。因此不跨 benchmark 比较
  绝对的触发召回，只在同一 benchmark 内比较各臂。
- 本地 folder 提示词没有 TB 的 `skill_read_suffix`（两阶段选卡、读后复述、完成前自检）。
  本地版允许在任何一步打开卡片，对应"晚一点再选"，但没有复述和完成门。
- 存储的步骤里读取是独立的一步，轨迹步号包含读取步；`steps_used` 小于 `len(steps)`。

## 已知边界

- 含 searchqa 或 alfworld 的旧 run 的 manifest 没有 folder 提示词的摘要，不能在新代码上
  续跑；新 run 按新摘要集合冻结。
- live 驱动还没有用真实的本地插件端到端运行。live 与 test 共用同一个任务挂载函数，插件侧
  由 test 相位的端到端测试和两个真实评测环境的冒烟覆盖；正式 live 运行前仍按外层
  AGENTS.md 先用 1 到 2 个任务冒烟。
- 读取上限和使用规则的措辞一旦用于正式 run 就不再修改。

## 验证

- 单元测试：读取语法与路径规范化、目录渲染与转义、循环的读取/上限/截断豁免、两个插件的
  folder 模式、`skill_use` 与 `skill_usage` 对本地读取的识别、folder 提示词与基础提示词
  只差读取文本。
- 端到端测试：真实 SearchQA 插件（评测仓库用桩）走 test 相位的 `folder` + `real_folder`，
  读取集进入相位摘要。
- 真实环境冒烟：真实 `searchqa-eval`（2000 题、真实评分器）一题读卡后答对；真实 ALFWorld
  引擎一局，读取步不进入游戏，4 步预算被 4 条游戏命令恰好用满。
- 全量测试 2564 通过，`ruff`、分层检查、私有信息扫描通过。
