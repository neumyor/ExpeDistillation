# TB 2.1 重跑前的修复

## 背景

TB 2.1 重跑前做了一次全流程评审：三路只读评审（执行侧、学习相位、运维），并实测导入 10-28 的摸底后跑到 p01（零模型调用、零 rollout）。评审发现三处会在正式 run 里卡住或丢数据，几处影响结果解读。用户逐条做了决定，下表是决定与实现。

## 决定与实现

| # | 问题 | 用户决定 | 实现 |
|---|---|---|---|
| 1 | playbook 写作是纯文本调用，一次空回复就让学习相位停下（退出码 1）；11-11 在同一网关上连续三次出现 | 修 | `methods/evolve_text`：`call_model` 抛出的模型输出错误也计入同一个重问额度（共 3 次）。`call_model` 本身不改：执行侧（ALFWorld、SearchQA 的执行循环）依赖空回复立刻抛出 |
| 2 | 写卡与归类时每段只截到 1,200 字符，TB 切段中位约 1.3 万到 1.7 万字符，只看到约 10% | 写卡与归类分开设上限：48000 / 6 / 4000 / 40 | `CardAuthoringParams` 新增可选参数 `typing_max_chars_per_segment`（缺省等于 `max_chars_per_segment`，ALFWorld 不变）；`build_paper_configs.py` 的 `AUTHOR_OVERRIDES` 只改 TB：写卡每段 48,000、每侧最多 6 段，归类每段 4,000、每块 40 段 |

| 4 | 无判分的 trial 我们不计入分母，外部 campaign 按 0 计 | 两种口径都报 | 新指标 `avg_at_n_invalid_as_failure`（每题成功数除以计划尝试次数，再对所有题平均），进相位摘要、`final_test_delta`、`paper-tables` 的汇总与配对比较；golden 重新生成，只多了这个字段 |

| 6 | 学习相位里模型调用失败的单元永久跳过，归类一块失败丢整块 | 修 | 学习相位的单元（诊断、切段、归类的段、画像、playbook、写卡、改写）模型输出失败时，每次运行记一行 `failed_units.jsonl`，相位在该步骤结束时以 `ResumableShortfall` 停下（退出码 3），下一次运行只重试这些单元；3 次运行都失败才放弃。归类失败的块对半拆开重试直到单段 |

| 8 | 运维：启动脚本一直挂着、续跑命令丢参数、旧监督脚本不适用、没有审计脚本、干净部署会带上未跟踪文件、`.env.example` 不全 | 照方案做 | 启动后立即返回并写 `<run 目录>/launch.sh`；新的本机监督脚本 `scripts/remote/supervise_run.py` 只在退出码 3 时续跑，连续 5 次没有进展就停下；`scripts/audit/audit_run.py` 自动核对设计正本第七节 6 项并加 TB 检查；干净部署从 `git archive HEAD` 导出；补全 `.env.example` 与 `scripts/remote/README.md` |

## 独立评审后补的修复

- 同一张卡在一个相位里先改正文、再改触发条件：正文改写失败、等待下一次运行时，触发条件改写也暂缓。否则触发条件改写先写出新版本，下一次运行会把正文改写误认作"已写完"并补一条成功回执；
- playbook 或画像在 3 次运行后放弃时，沿用上一个学习相位的文本和版本号，不记本相位的笔记来源；
- `paper-tables` 读到这次改动之前写的相位摘要（没有新指标）时跳过这一项交叉核对，数值照常从答卷重新计算。

## 不变的部分

- 所有提示词 digest 不变；44 份配置里只有 `tb21_paper_e1_ours.yaml` 变；
- 没有失败时 ALFWorld 与 SearchQA 的行为与产物不变；golden 只多了新指标字段，模型调用数仍是每个组合 35 次；
- 审计脚本在 g49 上一个已完成的 ALFWorld 正式 run（`alfworld_paper_e1_p1_r3_20261116`）上实跑，30 项 0 FAIL。

## 未验证

- 启动脚本、监督脚本在基准主机上的实际行为（GNU `stat`、`/proc`）只在本机用替身测过；
- TB 新参数下写卡调用的真实耗时与空回复率，要在小样本干跑里看。
