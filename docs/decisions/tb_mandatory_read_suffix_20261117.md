# TB 强制读卡后缀的开关

## 背景

8 次跑完 39 道 TB 测试题的 qwen run 里，avg@3 最高的是 10-29 的
`tb21_p02p06_exam_small20_node2_20261029`（0.5214，61/117）。它是唯一一次使用旧后缀的终测：
后缀要求第一条任务命令之前至少 `cat` 一张卡，117 个 trial 里 112 个读过卡。之后的终测都用
"卡可选"的新后缀，读卡率在 3% 到 14% 之间，avg@3 在 0.453 到 0.491 之间。

11-12 用 10-29 的同一个 17 张卡的库只换后缀重跑终测，avg@3 降到 0.4701（按题配对 −0.051，
95% 区间 [−0.120, +0.017]，3 胜 7 负）。差值跨 0，不能确认是后缀的作用；10-29 那次也有
可核实的运气成分（`docs/reports/tb21_suffix_playbook_attribution_20261112.md`）。用户决定
直接测试旧后缀。

## 候选方案

1. 把 `TB_SKILL_READ` 的文本改回旧版：所有 TB run 都会变，现有配置失去"卡可选"这个条件。
2. 给 folder 交付加参数，旧后缀作为一个具名提示词登记在 TB 插件下，由配置选择。

选 2。旧条件和现条件都能按配置复现，各自的提示词 digest 都冻结在 manifest 里。

## 做法

- `folder` 交付新增 `read_rule`：`optional`（缺省，插件的文件夹提示词）或 `mandatory`。
  `mandatory` 写进清单的 `read_rule` 键；缺省不写这个键，清单与改动前逐字节相同，单元编号不变。
- 插件接口新增 `skill_folder_mandatory_prompt_name`（缺省 `None`）。冻结步像冻结
  `skill_folder_prompt_name` 一样冻结它；没有声明的插件遇到 `mandatory`，相位驱动在派发前
  拒绝，E1 逐单元再拒一次。ALFWorld、SearchQA 不声明。
- TB 声明 `TB_SKILL_READ_MANDATORY`，文本是 10-29 那次终测 117 个 trial 收到的后缀原文
  （1,421 字符，sha256 `0c0e5ec0…788f27`，测试钉住）。它代替 `TB_SKILL_READ` 加
  `TB_DISCIPLINE`：只含当时的读卡要求、shell 卫生与阈值留余量，没有新后缀的完成前检查。
  有 playbook 时 playbook 仍在后缀最前面。

## 实验

配置 `configs/experiments/tb21_ours_mandatory_read_20261117.yaml` 与 `tb21_paper_e1_ours.yaml`
只差终测交付的 `read_rule: mandatory`。新 run 用 `fork-run` 从
`tb21_paper_e1_ours_20261116_1612` 复制 p01 到 p06（31 张卡的库与第 3 版 playbook 不变），
只跑 p07 终测，39 题各 3 次，与 11-16 的终测只差后缀。

事先写定的读法：

- 主指标是 avg@3，与 11-16 的 0.4701 和外部对照 0.4872 按题配对比较，报告按题自助法区间与
  胜负平；
- 每题 3 次时可检测的最小差约 0.11。差值小于这个量时，结论只能是"测不出差异"，不能说后缀
  有效或无效；
- 只跑这一次，用这一次的结果；
- 这个条件是看过终测成绩之后选出来的，若结果用于论文，必须写明这一点，最好在保留题上复核。
