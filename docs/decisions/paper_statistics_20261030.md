## 范围

本文约定 `composites/paired_stats.py`（纯函数）和 `stages/paper_tables.py`（读 run、出表）怎么算、怎么读。
输入是已经跑完的 run：它的 test 相位里，带库臂与对照臂（裸弱模型）在同一批测试题上各有逐 trial 的判分。
代码只读 run 目录，不调模型，不写 run 目录（输出路径落在任一输入 run 内会直接报错）。

## 预先登记的指标

三个口径沿用 `blocks/metrics.py` 与 README 5.5，现在登记为论文表格的口径，看结果之前固定，之后不改、不挑：

1. **avg@N（条件口径，论文表格默认展示的主指标）**：每道题先对"有判分的 trial"求平均，再对至少有一个
   有判分 trial 的题求平均。没有任何判分 trial 的题没有成功率，不进分子也不进分母。
2. **avg@N（保守口径）**：所有题都进分母，没有判分 trial 的题记 0。每道题的成功率仍然只在它自己有判分的
   trial 里求平均。
3. **pass@N**：至少有一个成功 trial 的题占全部题的比例。没有判分 trial 的题进分母、不可能通过。

表格 markdown 一次只展示一个口径（`--metric`，默认 avg@N 条件口径），JSON 永远三个口径一起写。
`load_arm` 会从逐 trial 的 answer sheet 重算三个数，与 `phase_summary.json` 里的值逐项比对，任何一项对不上
就报错，所以表格里的数不可能悄悄换了定义。

**哪些 trial 算"有判分"**：判分结论为成功或失败的 trial。判分结论为 invalid（判分器没给结论）、
从未判分、缺失（`missing`）和已接受的空洞（`accepted_hole`）都不是有判分 trial：它们不记 0，只从所在题的
平均里拿掉，并按任务和序号列在 `meta["unscored"]` 里，表格脚注也会写出各臂的数量。

**trial 得分**：成功记 1.0，失败记 0.0。统计函数本身接受 [0, 1] 内的任意得分（部分得分的外部奖励也能算），
此时 avg@N 对得分求平均，pass@N 只把满分（等于 1）算成功。目前外部对照的加载器只收 0/1 奖励，
所以论文表格里的得分都是 0/1。

## 为什么按题做自助法

同一道题的几次 trial 来自同一个任务和同一份技能库，彼此不独立。把 trial 当独立样本会把区间压得过窄。
论文要回答的是"换一批题，结论还成立吗"，所以抽样单位取题：

- 每道题先求出带库臂与对照臂（或两个臂）各自的题内均值，两者相减得到这道题的差；
- 有放回地重抽题（样本量等于题数），重算差的平均，重复 `n_boot` 次（默认 10000，种子默认 0）；
- 取这些平均的 2.5% 与 97.5% 分位数（线性插值）作为 95% 区间。`level` 可改。

只在两个臂都有的题上配对。只在一个臂里出现的题单独列在 `only_a` / `only_b`，不进差。条件口径下，任一
臂没有判分 trial 的题从这次比较里拿掉，列在 `excluded_unscored`，脚注写出个数；保守口径下它在没有判分的
那个臂记 0，不拿掉。两个臂没有任何公共题时直接抛 `ValueError`。

`wins` / `losses` / `ties` 比较每道题的题内均值，用 `fractions.Fraction` 精确计算（0.1 与 0.2 的平均
恰好等于 0.15，浮点误差不会把平局算成输赢）。

已知限制：自助区间只反映"换一批题"的波动，把每道题的题内均值当成已知值。题数很少时（TB 的 39 题）区间偏窄
且取值离散，读区间时要结合 W/L/T 看。

## pass@N 的检验

pass@N 的配对比较在"至少一个成功"这个 0/1 指标上做，区间同样按题自助。另外给出 McNemar 精确检验：
设 b 为只有 A 臂通过的题数，c 为只有 B 臂通过的题数，n = b + c，则

    p = min(1, 2 × Σ_{i=0..min(b,c)} C(n, i) / 2^n)

n = 0 时 p = 1。检验只看两臂结论不同的题，不依赖正态近似。表格在 pass@N 视图里把"控制组噪声"一列换成
带库臂对本 run 对照的 McNemar p。

## 噪声底怎么读

噪声底回答"同一个臂再跑一次，平均值会自己波动多大"，也就是这套测量能分辨的最小差。做法：对一个臂，把每道题的
k 个 trial 随机分成相等的两半（k 为奇数时随机丢掉一个），用两半各自的臂均值相减，重复 `n_resample` 次
（默认 2000），记录这些差的标准差 `sd` 与 95% 区间。表格里的"control noise SD"取本 run 对照臂的 `sd`。

读法：

- 每一半只有 k//2 个 trial，比完整臂少，所以 `sd` 偏大。JSON 里的 `sd_at_full_depth` 按 √((k//2)/k)
  换算成"两个完整深度的臂相互比较"的标准差（所有题 trial 数相同时才给，否则为 None）。
- 带库臂相对对照的差小于 `sd`，可以直接判定落在重跑噪声之内。介于 `sd_at_full_depth` 与 `sd` 之间的差，
  只有在同时满足"自助区间不含 0"时才值得报告，并且论文里要写出噪声底。
- 噪声底只覆盖"同一份技能库、同一批题、重新采样 trial"的波动。它不覆盖"重新学一遍技能库"的波动：
  每个臂目前只学了一次，两次独立学习之间的差异没有被测量，不能用噪声底代替。
- 对照臂如果每题只有 1 个 trial（或外部对照没有逐题多次采样），无法分半，表格显示 n/a。

## 表格规则

- 行、列、表的顺序完全按 spec 文件，绝不按结果排序，不加粗，不自动标最好。
- 每个格子写 `带库臂指标（对本 run 对照的差 [区间]）`；一列写 W/L/T，一列写对照臂指标，一列写噪声底
  （或 McNemar p）。spec 里的 `references` 为某个实验指定参照臂时，其余臂再多一组对参照臂的差与 W/L/T，
  比较的是两个臂带库的得分，不涉及参照臂自己的对照。
- 参照臂与另一臂的执行者模型不同时（实验二的教师→学生矩阵），脚注逐臂写明，提醒这一列比较的是不同模型。
- 各格是独立的比较，没有做多重比较校正。表格里不给出"显著"或"最优"的结论，写论文时按本文的读法逐格解释。
- 每个表的脚注写出指标定义、自助次数、种子、噪声底的算法；未判分的 trial 与被拿掉的题另起一行说明。

## 数据来源

主数据是 test 相位的 `answer_sheets/`、`unit_specs.jsonl`、`coverage.jsonl` 与 `phase_summary.json`。
外部 campaign 对照（TB 的裸跑归档）读法相同：它的每个奖励在 test 相位里已经是一份 answer sheet。
一个 run 里有多个 test 相位时必须指定标签；找不到完成信号（缺 `phase_summary.json`）的相位直接报错。
spec 里每个 benchmark 键必须与 run 冻结的 benchmark 一致，避免把 run 放到错的表里。
