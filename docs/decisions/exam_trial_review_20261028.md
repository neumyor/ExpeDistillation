# 决定：exam 相位的 trial_level 按纸面答卷分析，动作只取自技能自己的考题

日期：2026-10-28
一句话：exam 相位的 `trial_level` 改用专门的答卷分析提示词，并规定每个技能的动作、改写证据和下一次考题的切点都只来自它自己的考题。
对应 log.md：2026-10-28 的“exam 相位 trial_level 的答卷分析与考题契约”条目。

## 背景

run `runs/tb21_p02p06_exam_small20_20261028_1322/`（P03/P05 exam，P04/P06
trial_level）的 P04 / P06 动作经逐题核对，暴露两处缺陷。

1. 复盘把纸面答卷当成执行轨迹。`TRIAL_FAILURE_ANALYSIS` 收到的是“读技能 +
   一段计划、observation 为空”两步，提示词按终端 agent 的执行轨迹措辞，输入里
   没有裁判判词和期望行为。P03 的 30 条判错理由中没有一条批评“只写计划不发
   命令”，P04 的复盘却把 21 个“考错但保留”中的 16 个归因为“写计划不执行”，
   P06 的 13 个保留中也有 10 个是这个理由；裁判指出的具体缺陷（例如“改完源码
   没重装就重跑测试”“直接对原库操作没先拷贝”）没有进入复盘。这个误读还写进
   了累积的模型画像，并产生了“下一步必须是一条具体命令”这类与答卷格式冲突
   的新需求技能。
2. 改写依据取错了考题。聚合时 revise 行的 `basis_unit` 取第一个提到该技能的
   finding，改写证据取最后一个提到它的 finding。一张答卷交付整个技能目录，
   一条 finding 会提到多个技能，所以 P04 的 9 条改写里有 8 条的依据和证据来自
   别的技能的考题。`learn_exam` 用 basis 对应考题的 `scene` 记录 v2 的
   来源，于是 P05 在别的技能的切点上考这些 v2：6 条的切点早于自己的锚点段
   （例如训练结束后的最终校验技能，被放在下载还没完成的第 26 步考），复盘只能
   得出“技能还没到适用阶段”。这 9 条改写本身大多有依据：其中 8 条在自己的考题
   里确实没被打开。

## 候选方案

- 让 exam 真实执行：考试变成第二个 P07，成本和波动都上升，也失去逐技能单独
  考的作用；
- 让 `EXAM_PLAN` 要求输出命令：改变考试形式和裁判标准；
- 改写时保留别的考题作依据，另加“切点必须落在锚点段内”的程序检查：依据和
  证据仍来自别的场景，需求技能没有锚点段也无法检查；
- 复盘按答卷事实分析，动作只认技能自己的考题（采用）。

## 决定

1. 新增提示词 `TRIAL_EXAM_ANALYSIS`，只用于 exam 相位，输出格式与
   `TRIAL_FAILURE_ANALYSIS` 相同，另有必填的 `exam_skill_issue`。输入取自答卷：
   场景、期望行为、裁判判词、被考技能正文、作答时看到的目录、实际打开的技能、
   计划。答卷构建时把考题的 `expected_behavior` 写进 `metrics`（新增可选
   字段）。参考答案不进入复盘，避免场景细节被写进改写后的技能。
2. 提示词规定：计划不带执行输出是答卷格式；以裁判判词为准解释缺陷；只讨论
   这个切点上适用的技能；对被考技能给出四种情况之一（触发缺陷 / 模型选错或
   场景不在它的阶段 / 模型局限 / 内容缺陷）。finding 的第一个技能固定为被考
   技能。
3. 聚合把每条 finding 的逐技能问题（`SKILL_ISSUES`）一起交给聚合模型。
4. exam 相位的聚合：基准单元是技能本相位最高版本的考题；revise / delete 只能
   由这道考题的失败 finding 支撑，否则保持 keep；revise 证据取自这道考题的
   答卷；本相位没考到的技能不产生动作行。
5. live 相位的输入、提示词和动作规则不变。

## 理由

- exam 的契约是“一题一个技能”（`decision._exam_target`：考题 id 就是地址），
  动作只认自己的考题与这个契约一致；
- 改写后的版本回到自己原来的切点重考，P03 → P05 成为同一技能、同一切点的
  配对比较，能直接看出改写是否修好了原来的失败；
- 改动集中在复盘的输入和聚合规则：一个提示词、`methods/review/trial.py` 的
  exam 分支、`methods/review/aggregation.py` 的 exam 规则和一个答卷字段，
  考试形式、裁判、决策规则表都不动。

## 已知边界

- 同一切点重考检验的是修补是否有效，泛化效果由 P07 的留出集真实执行检验；
- 技能在别的考题里被打开并把计划带偏、自己却考过了的情况，不再单独触发
  改写；这次 run 里这类技能的动作本来都是 keep；
- `EXAM_SCENE` 的期望行为有时覆盖切点之后的整个剩余任务（这次 run 的 30 条
  判错里约 3 条），本决定不改考题生成；复盘能看到期望行为，可以在理由里指出；
- 新提示词进入 manifest 的提示词摘要，这是新的实验身份，旧 run 不能在新代码
  上续跑。
