## 背景

folder 版 C 终测实验的装配干跑（--until-phase 5 + 拒答端点）暴露：装配 run
的第一个学习相位给 30 个"弱模型失败且库里没有技能"的训练任务全部发了 add
行。29 个在落盘一步被既存技能挡住（skipped_existing），但
custom-memory-heap-crash 在源 store 里没有任何技能（源 run 自己的协议就没
为它产出过技能，其弱臂 3 次里成功 2 次），add 行真实触发了切段与写作调用。
放任下去：B 相位要为这条新技能真实执行 3 次远端测量（基准主机），终测的库
可能长成 142 条——装配 run 本来要冻结复测的 141 条库（bank:a340288b1562）
就被改写了，实验前提（"D/L/B 零调用，C 测冻结库"）失效。

## 根因

`phase_learn._previous_bank` 对序列里第一个学习相位恒返回空库（"第一个学习
相位从空库开始"）。决策的"库里还没有技能"按锚定任务判覆盖；空库覆盖为零，
于是 30 个弱失败任务全部获得 add 授权。而 `assemble_reuse` 的模块文档明确
写过 run 根库是"the pre-learn bank fallback"的读取对象——交付侧
（`_bank_skills`）已经实现了这条回退，学习侧没有，文档与代码不一致。

## 裁决

第一个学习相位没有上一工件时，回退读 run 根的冻结库（与交付侧
`_bank_skills` 同一条规则）：

1. **从零 run 行为不变**：v4 相位管线只写相位工件，run 根库在首学习相位
   时尚不存在（read_jsonl 对缺失文件返回空表），回退读空，等价于原来的
   空库开始；
2. **装配 run 语义补全**：预置库（141 条）成为首学习相位的决策输入，其
   锚定覆盖的弱失败任务不再重发 add（30 → 13 行，且 13 个全部走
   skipped_existing 落地，零模型调用），预置库保持冻结；
3. **不挡路径**：库没有锚定覆盖的弱失败任务照发 add——回退只是把 add
   收窄到真正没被冻结库覆盖的任务，装配 run 若真有这种缺口（本次没有）
   仍会被如实暴露为待补材料。

## 后果

1. README 5.6 的"第一个学习相位从空库开始"改为回退描述；
2. 端到端装配测试（零调用重放）的期望从"add:1 + skipped_existing"改为
   "零行零回执"（夹具的预置库恰好锚定覆盖该任务），新增 w2b 双例钉住
   "覆盖→不发"与"未覆盖→照发"；
3. 本裁决与 token_budget 无护栏拼写（同日另条）合起来，folder 版 C 实验
   的装配干跑才真正零调用。
